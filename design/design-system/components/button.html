Button

Five variants, three sizes. Shape is a superellipse at radius 12; press is a 0.97 scale over 120ms — never a ripple, which is Material's signature. Every colour here is a parameter with a token default, so a host app can restyle without touching logic.

Sizes & the 48dp touch target

Visual heights are 36 / 44 / 52. The dashed outline is the interactive area: always at least 48dp tall, even when the button is drawn smaller. Most libraries let the small size ship a 36dp target and fail accessibility — the target is part of the design, not an afterthought.

rest · pressed (0.97) · disabled (38%) · loading

Loading reserves the button's resting width so the layout never jumps — a jump on tap is the cheapest-feeling thing an app can do.

Proof: the same component in three host themes

This is the real test of the system. Identical geometry, spacing and motion — only the token values change, as they would in someone else's app. If the button is still recognisably ours in all three, the identity is structural rather than cosmetic.

Compose API shape

JetButton(onClick, modifier = Modifier, variant = Primary, size = Medium, enabled = true, loading = false, leadingIcon = null, trailingIcon = null, colors = JetButtonDefaults.colors(), content: @Composable RowScope.() -> Unit)

modifier is the first optional parameter, state is hoisted to the caller, and the label is a slot rather than a String so callers can compose freely — per the AndroidX component API guidelines. Colours come from a defaults object so a host app can override one role without redefining the component.
